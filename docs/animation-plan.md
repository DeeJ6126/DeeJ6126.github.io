# Dee's Blog 页面动画设计与实现计划

> 依据 `Blue Sky.mp4`（29.184 秒、1920x1080、30fps）重新拆解。正式实现前已补做 6fps 密集观察帧，存放在 `.dsh-vision-toolkit/blue-sky-dense/`。本文件只定义动画，不改动课程、项目与关于页的内容结构。

## 1. 设计结论

Blue Sky 的重点不是“很多方块在动”，而是同一批几何材料不断改变组织关系：

1. 单点或线框建立视觉焦点。
2. 实心色块由小到大，形成主视觉。
3. 一个色块分裂成多个模块，模块之间出现细线连接。
4. 模块重新排成文字、横带、嵌套矩形或图片序列。
5. 画面完成表达后迅速收束，只留下少量元素作为下一段的起点。

因此站点动画采用“同一组蓝色几何模块在页面之间重新编排”的方法，而不是给每个元素单独做淡入淡出。动画是内容之间的标点，不是持续播放的背景。

明确排除：

- 不使用取景框式转场。
- 不让整个页面长时间缩放或旋转。
- 不使用模糊、光斑、3D 或大面积渐变遮罩。
- 不在详情页内容区域加入循环动画。
- 不复刻视频中的大号英文排版；只借用其几何运动逻辑。

## 2. 视频时间轴拆解

### 0.00-0.80 秒：建立入口

黑底中出现极细的方形线框，线框不是一次完整显现，而是从短线段逐步闭合。随后黑底迅速退出，画面切换到浅色纸面。

可复用语言：线段闭合、中心锚点、黑白反转。

### 0.80-4.80 秒：单块分裂

中心蓝色方块从小尺度稳定下来，随后复制、错位并排列成一组横向图片块。运动以直线位移和尺度变化为主，停顿短但清楚。

可复用语言：中心实心块、五段拆分、轻微错位、由单体到集合。

### 4.80-7.20 秒：网络形成

矩形数量快速增加，深蓝、天蓝和浅蓝块分布到画面两侧，细线在块之间建立关系。构图由横排变为网络，但仍然保持大量留白。

可复用语言：模块扩散、节点连线、非对称平衡。

### 7.20-10.80 秒：横带与文字重组

网络被压缩成中心横带，色块和文字沿同一水平轴排列；随后局部再次爆开，形成下一段的材料。这里的关键不是切换场景，而是旧构图被重新排版。

可复用语言：水平扫动、条带压缩、沿基线重排。

### 10.80-14.80 秒：嵌套空间

云图与矩形边框连续复制，形成向画面深处收缩的嵌套结构。荧光黄绿只在关键字和短色条上出现，用于给蓝色系统制造一次高对比脉冲。

可复用语言：同心矩形、分级延迟、单次荧光强调。

### 14.80-20.20 秒：轻节点叙事

构图重新缩小，少量图片节点沿折线路径出现；文字从不完整字符逐渐组成完整短语。随后云块、线条和小方块扩展为宽幅但轻盈的图谱。

可复用语言：路径生长、逐字组装、局部到宽幅。

### 20.20-25.80 秒：飞行与收束

鸟的连续姿态形成方向明确的运动线，周围的几何碎片被带动并汇聚到中心。之后整个复杂构图缩成一个很小的中心群组。

可复用语言：方向性队列、尾随碎片、中心压缩。

### 25.80-29.18 秒：结束标点

只保留一个小型轮廓方框与极少量蓝色元素；荧光绿短暂替换中心色块，最终回到黑底线框。首尾形成闭环。

可复用语言：减法收尾、单次色彩脉冲、闭环。

## 3. 站点动画系统

站点需要四种动画。四种动画共享颜色、方块、细线与时间曲线，但各自表达不同的导航层级。

### A. 首次进入站点：页面骨架的自组装

时长目标：约 1.7 秒（上限 2.0 秒），仅每个浏览器标签页首次进入时播放一次。

开场不再是黑屏片头，而是“这个网站被组装出来”的过程：视频的运动语法（单块建立焦点、分裂、沿细线重排、单次荧光强调）全部保留，但材料换成站点自身的结构——1px 结构线、左轨学科方块、课程封面构成。

时间线：

1. `0-530ms`：纸面直接可见，无黑屏。覆盖层在页头底部与左栏右侧画出 1px 结构线（页头线横向扫出，左轨线纵向落下），页头文字沿基线浮入；左轨此时尚未出现。
2. `500-860ms`：三枚深蓝方块在内容区中心纵向依次出现。
3. `860-1660ms`：三枚方块依次出发、快速飞向左轨，各拖一条细线；每一枚落位时，左轨对应的学科条目（生物科学/生物信息/人工智能）才随之浮现并点亮（蓝、墨蓝、天蓝），方块随即淡出，位置交还给真实 UI。无左轨的页面落到页头导航三项，语义不变——“站点的三个分区由此诞生”。
4. `1400-2320ms`：真实内容按落点节奏自上而下逐段浮现（学科区、封面、文字），首张封面角落闪一次荧光绿（约 1720ms），作为整套蓝色系统的标点。
5. `1860-2080ms`：骨架线淡出，交还给真实边框；覆盖层退出，页面完整可用。

规则：

- 全程在纸面上进行，不使用黑底与黑白反转；磨损网点质感不复刻。
- 开场落点必须是真实页面元素（左轨方块或导航、封面），让“几何变成界面”的因果可见。
- 使用 `sessionStorage` 记录本标签页已播放；刷新、详情返回和站内切换不重复播放。
- `prefers-reduced-motion: reduce` 时完全跳过；`is-intro-playing` 类在首帧绘制前添加，任何失败路径都会移除，不阻塞内容。

### B. 课程 / 项目 / 关于之间切换：鸟群接力

时长目标：700-850ms。

时间线：

1. 从视频飞行段提取的鸟群从导航方向进入，前方或后方保留一块蓝色主方块。
2. 当前首屏的六个真实页面锚点收成深蓝、蓝、天蓝与浅蓝小块，跟随鸟群汇聚到画面中央。
3. 路由交换后，鸟群继续飞离；小块不组成额外的栏目片头，而是直接落向目标页面的导航、标题、主视觉与文字链接。
4. 正向切换向右飞，反向切换镜像为向左飞；页面完成后覆盖层立即销毁。

鸟群透明素材位于 `source/img/motion/bird-flight.png`，由 `Blue Sky.mp4` 对应区间提取，不使用通用鸟图标。

### C. 进入课程详情：完整封面接力

时长目标：680-820ms。

点击课程封面、课程名或“进入课程”都使用同一种入口：

1. 读取被点击课程卡片中 `.course-cover` 的屏幕位置与主色。
2. 用覆盖层克隆完整封面，保持同一张图片与相同的 `cover` 裁切逻辑。
3. 完整封面先从长卷中轻抬并移动到中央停顿位置，始终不切片、不复制。
4. 路由交换后，封面连续改变尺寸与裁切比例，移动到详情页 `.hero-geometry` 的真实位置。
5. 三个小型蓝色引导点落向左侧导航、学科标签和封面边缘，真实详情封面随后接管。

这是一种“同一份学习材料被带入详情”的动作，封面本身始终是唯一主角。

### D. 进入项目详情：图像节点化并重组

时长目标：820-960ms。

1. 读取 `.project-visual` 的位置与封面图。
2. 封面缩为中心主节点，周围生成 6-10 个蓝色小节点。
3. 细线从主节点向外依次生长，构成一帧简洁网络。
4. 所有节点沿直线路径移向详情页 `.project-cover`，重新合为完整项目图。
5. 项目标题与元数据在最后 180ms 出现。

项目详情页落地后保持静态。这里的“无动画”解释为内容不循环、不滚动触发、不自动漂移；只有进入页面前的一次性转场。

### 返回列表

详情页左上角返回按钮和浏览器后退统一使用 B 类水平重排，不强行做完整逆向共享元素动画。这样不会依赖用户返回前的滚动位置，也避免封面飞向一个不在视口中的卡片。

## 4. 统一视觉参数

颜色只使用站点已有变量：

```css
--motion-ink: #17336c;
--motion-blue: #1265f3;
--motion-cyan: #78cdf9;
--motion-pale: #d7eaff;
--motion-lime: #caff35;
--motion-paper: #f6f7f5;
```

荧光绿只允许在开场末尾或转场中出现一次、持续不超过 140ms，不作为常驻背景。

缓动：

```css
--motion-enter: cubic-bezier(.22, .72, .18, 1);
--motion-exit: cubic-bezier(.7, 0, .84, .24);
--motion-shift: cubic-bezier(.4, 0, .2, 1);
```

几何限制：

- 全部元素保持直角或最多 2px 圆角。
- 连线宽度为 1px，透明度不高于 0.28。
- 同屏活动节点上限 24 个，课程详情只允许一个完整封面克隆。
- 覆盖层层级低于鼠标拖尾、高于页头和内容。
- 不改变真实页面布局，不让动画元素参与文档流。

## 5. 技术方案

采用 Astro 自带 `ClientRouter` + 一个跨页面持久化的 Motion Layer，不引入 GSAP、Barba 或其他动画库。

原因：

- 当前项目是 Astro 7.2.4，已包含 `astro:transitions`。
- 四种动画只需要 Web Animations API、CSS transform/opacity/clip-path 和少量 Canvas 连线。
- 避免额外依赖和运行时体积，也便于逐种动画单独调整。

组件边界：

```text
SiteLayout.astro
  ClientRouter
  SiteHeader
  page content
  MotionLayer (persist)
  CursorTrail

site-motion.js
  intent capture
  Astro navigation lifecycle
  timeline selection
  cleanup and fallback

motion-timelines.js
  intro timeline
  section timeline
  course-detail timeline
  project-detail timeline
```

Motion Layer 只负责一次转场；鼠标拖尾继续使用现有 `CursorTrail`，两者不合并，防止鼠标粒子状态被页面切换重置。

## 6. 文件改动范围

新增：

- `src/components/MotionLayer.astro`：持久化覆盖层、几何节点容器与无障碍属性。
- `src/scripts/site-motion.js`：捕获导航意图、控制 Astro 页面事件、选择时间线与清理状态。
- `src/scripts/motion-timelines.js`：四类动画的纯函数时间线。
- `src/styles/site-motion.css`：覆盖层、色块、连线和 reduced-motion 样式。
- `test/site-motion.test.js`：意图分类、开场状态和时间线参数测试。

修改：

- `src/layouts/SiteLayout.astro`：加入 `ClientRouter`、`MotionLayer` 与全局动画样式。
- `src/components/SiteHeader.astro`：导航链接增加 `data-motion="section"` 和目标栏目。
- `src/components/CourseEntry.astro`：三个详情入口增加 `data-motion="course-detail"`，并指向同一封面源。
- `src/components/ProjectEntry.astro`：详情入口增加 `data-motion="project-detail"`，并指向同一项目视觉源。
- `src/pages/courses/[slug].astro`：标记 `.hero-geometry` 为课程转场目标。
- `src/pages/projects/[slug].astro`：标记 `.project-cover` 为项目转场目标；内容本身仍保持静态。
- `src/pages/about.astro`、`src/pages/index.astro`、`src/pages/projects/index.astro`：增加页面类型标记，用于决定标准栏目转场的结束构图。

不修改：

- `source/_posts/`、`source/_data/`、`source/files/` 和课程笔记内容。
- `source/img/course-covers/`。
- 项目详情的文案结构与成果图片。
- 现有鼠标拖尾算法，除非动画 QA 发现层级冲突。

## 7. 导航与失败保护

1. 只拦截同源、左键、无修饰键的内部链接。
2. `target`、下载链接、锚点、外部链接和新窗口链接保持浏览器默认行为。
3. 动画状态最长 1200ms 自动清理，任何异常都直接完成导航，不留下遮罩。
4. 页面切换期间只屏蔽重复导航点击，不阻塞滚轮和系统返回操作。
5. 转场完成后恢复焦点；详情页优先聚焦主标题，列表页聚焦主内容容器。
6. 开场和转场覆盖层使用 `aria-hidden="true"`，不向屏幕阅读器暴露装饰元素。
7. 浏览器不支持 View Transitions 时仍通过 ClientRouter 生命周期和 Web Animations API 工作；脚本加载失败时退化为普通页面跳转。

## 8. 实现顺序

### 阶段 1：动画基础设施

- 加入 `ClientRouter` 和持久化 Motion Layer。
- 建立导航意图分类与统一清理机制。
- 先实现一个纯色方块测试时间线，确认页面切换不会闪白、不会重复绑定事件。
- 完成 reduced-motion 与脚本失败退化。

验收：普通导航、后退、刷新、直接打开详情页全部可用；关闭动画后页面行为与现在一致。

### 阶段 2：首次开场

- 实现骨架线绘制、文字基线浮入、三枚方块点亮学科导航与内容浮现。
- 接入 `sessionStorage`，确保每个标签页只播放一次。
- 先在课程页对齐左轨落点，再验证直接进入项目与关于页面的情况（落点退化为页头导航）。

验收：总时长不超过 2.0 秒；首帧不闪现完整页面；动画未完成前内容已渲染；无横向滚动条。

### 阶段 3：栏目切换

- 实现鸟群双向飞行、页面锚点收束与目标锚点落位。
- 接入页头三个导航入口与详情页返回。
- 检查快速连续点击、浏览器后退和跨页锚点。

验收：切换不超过 850ms；页头不跳位；搜索框状态不会残留到下一页。

### 阶段 4：课程详情转场

- 为课程卡片三个入口统一绑定封面源。
- 实现完整封面从列表到详情英雄图的连续迁移。
- 验证真实图片封面与纯 CSS 几何封面两种情况。

验收：无论点击封面、标题还是文字链接，动画来源一致；动画结束后详情页可立即滚动和阅读。

### 阶段 5：项目详情转场

- 实现封面主节点、小节点和连线生长。
- 将节点群重组成项目详情封面。
- 保持详情页落地后完全静态。

验收：动画只播放一次；Canvas/DOM 节点全部销毁；项目图片保持原比例。

### 阶段 6：回归与视觉校准

- 运行 `npm test`、`npm run check`、`npm run astro:check`、`npm run build`。
- 在 1280x720、1440x900 和 1920x1080 三个桌面视口检查四类动画。
- 以截图和像素检查确认覆盖层非空、结束后完全透明、无文字重叠和横向溢出。
- 用 Performance 面板确认过渡期间不持续触发布局抖动，结束后无残留 `requestAnimationFrame`。
- 检查 `prefers-reduced-motion`、直接 URL 访问、刷新、后退与脚本禁用退化。

## 9. 第一轮实现边界

第一轮只追求四类动画的动作正确、节奏明确、页面不闪烁，不追求逐帧复刻视频。完成后再根据实际预览逐项调整：

1. 先调开场的“三枚方块点亮学科导航”节奏。
2. 再调栏目切换的鸟群速度与锚点尾迹。
3. 再调完整课程封面的比例变化与落点。
4. 最后调项目节点数量和连线密度。

每完成一种动画就单独预览和确认，不在同一轮同时精修四种，避免运动语言互相干扰。
